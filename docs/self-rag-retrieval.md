# Self-RAG 检索与证据分析

本轮实现的是使用 Pi 通用模型的自反思检索流程：问题改写 → 多路召回 → 专门重排 → 证据覆盖评估 → 必要时补检索一次 → 带引用的分析 → 独立引用核对。没有训练论文 Self-RAG 的 reflection token 专用模型，也没有构建 GraphRAG。

## 召回和相关度

- 原始问题始终参与召回，最多补充三个中文、英文或子问题改写；补检索最多增加两个查询，整个流程最多两轮。
- 每个查询分别执行正文稠密向量、正文 BM25、元素稠密向量、元素 BM25，以及本地原文 BM25、标题元数据召回；识别图、表、公式或算法编号时增加精确编号召回。
- 本地词法索引使用中文词语、汉字二元组与英文分词，BM25 参数 k1=1.2、b=0.75。一次查询过程只构建一次倒排索引，改写和补检索复用。
- 加权 RRF 使用 k=60；按发布代次和正文／元素 ID 去重，同一路的扩写表示不重复增加分数。原问题权重 1、改写 0.65；精确编号乘 1.5、本地词法乘 0.8、标题元数据乘 0.6。保留每路的原始分数、排名、查询和融合贡献。
- 默认融合 60 个候选，取 32 个交给百炼 `qwen3.7-text-rerank`。按照真实返回的文档索引校验分数，禁止把不同召回通道的原始数值直接相加。
- 最终综合分数为 0.85 × 重排分 + 0.10 × 归一化融合分 + 0.05 × 时间适配分；未请求最新时最后一项为常量。重排离线会显式降级到融合分。
- 使用 MMR（λ=0.85）控制近重复结果；历史对比任务保留不同日期的相似来源。分数仅用于当前检索排序，不是正确率或跨请求的绝对相关度。

百炼接口和请求格式依据[官方重排文档](https://help.aliyun.com/zh/model-studio/text-rerank-api)。本地真实验证时 `qwen3-rerank`、`gte-rerank-v2` 的免费额度开关返回 403，`qwen3.7-text-rerank` 可用，因此后者作为默认模型。可以在设置 → 知识库切换模型、接口地址和预算。未指定重排地址时，沿用 Embedding 的地域和业务空间主机；重排凭据默认复用服务端百炼认证，也支持 `PIPAPER_RERANK_API_KEY`。

## 证据反思和时间

反思检查候选是否直接支持任务，以及是否覆盖各子问题。相关度不足的证据排除，覆盖不足时最多补检索一轮。分析只能引用这次返回的已发布原文或已核验元素；独立核对检查数值、否定、对象、日期和替代关系，撤回不受支持的结论和时间偏好。模型非法 JSON 允许一次格式纠正；没有完成核对时仅展示原始证据和原因。

支持自动、相关性优先、近期优先、截至日期、日期区间与历史对比六种时间策略。问题中的明确截止时间／年份范围优先于近期偏好；年份精度保持为年份，不能显示为一个已知的具体发表日期。

原始文献使用元数据中的发表日期／年份，不使用导入时间或文件名年份。笔记和报告的成果生成时间与其来源论文发表时间分别标注。新发布代次冻结来源元数据；旧代次在来源更新后使用历史版本的日期，无法定位历史日期时标记未知。未来年份、日期精度不足和未知日期都有警告。截止日期之外的已知来源排除；未知日期保留并提示无法确认适用性。

相似来源优先用原始证据 Embedding 的余弦相似度识别（默认 ≥0.9），不可用时使用文本词语重叠。不同日期的相似证据不直接合并，返回日期依据、推荐理由和差异警告。日期较新不等于方法更好，向量相似不证明新结果取代旧结果。

**最新判断的范围是本地已入库资料。** 未联网核验时会明确提示无法确认全球最新进展。当前检索不会自动将外部论文搜索结果作为可回答的原文证据。

## 前端、Pi 与扩展接口

检索工作区提供 Self-RAG 开关、来源／元素／项目筛选和时间策略，实时显示阶段并支持停止。分析在上方，引用按钮跳转到下方证据；每条证据展示片段、标题路径、页码、版本、日期依据及独立图表公式区。共享附件仍按代次与元素 ID 去重并链接到首次展示位置。

- `POST /api/rag/search` 返回普通 JSON；`POST /api/rag/search/stream` 返回 NDJSON progress/result/error 事件，断开连接取消模型调用。
- 参数：query、resourceIds、projectId、sourceType、elementType、limit（最多20）、imageBudget（最多12 MiB）、selfRag、temporal（mode/from/to）。HTTP 不接受客户端注入模型、向量库或扩展服务。
- 返回：results、analysis（claims/citations/verified/gaps/comparisons/status）、warnings、temporal、retrieval（改写、召回来源、轮次和阶段耗时）。原文与完整附件始终来自同一发布代次。
- Pi `search_knowledge` 提供相同自反思流程和时间参数，`get_knowledge_element` 保留附件按预算加载能力。
- 只调整检索／重排参数不会使既有索引过期，也不触发全库重建。
- `registerRetrievalProvider(name, retrieve)` 是未来独立图谱应用等检索提供方的接入口，当前没有注册图谱提供方。提供方收到问题、改写、时间约束和允许的资源／代次范围；返回结果仍须通过 SQLite 发布状态、范围与元素类型校验。图谱数据的建立和存储不属于此检索模块。

所有外部调用结束后，返回前再次校验生命周期与发布代次；期间删除或切换版本会撤回相应证据、分析及引用。

## 验证与限制

针对性测试覆盖双语 BM25、加权融合、日期精度、时间窗口、相似来源保留、补检索上限、引用及时间偏好撤回、服务降级、迟到删除、旧版本日期，以及扩展提供方范围隔离。HTTP 测试验证真实 Pi 运行时、流式阶段、表格证据及检索配置不影响索引发布。

`node --use-system-ca scripts/retrieval-evaluate.mjs` 使用隔离数据目录和临时 Milvus 集合，对固定30条中英文问题比较融合和重排的 Recall@10、MRR@10；不会修改用户文献。真实结果保存在忽略目录 `data/validation/self-rag-ranking.json`。本轮融合与重排两项指标均为1.0，这组样例已达到上限，不能据此宣称重排提高了准确率；该基准验证了连接和不退步，尚未覆盖困难负例、真实多文献时间冲突或全流程 Self-RAG 的大规模准确率。

真实 RRNCO 文献通过百炼 Embedding、Milvus、百炼重排与 DeepSeek 模型验证了完整流程，并在浏览器中核对图、表、公式与分析引用。语言模型自核对不是事实正确性的数学保证；仍需用更丰富的人工标注问题持续评估。
