# PDF 复合解析与恢复

## 当前流程

1. PDF.js 读取原始页尺寸、文字和坐标，形成本地基准。
2. 优先读取 MinerU 的结构化 content_list；未配置或失败时使用已配置的 unstructured，再降级到本地文字提取。`自动选择引擎`保留旧的单引擎模式，默认入口为`复合解析`。
3. 结构化来源决定块类型和原始阅读顺序，直接换算坐标，不再先转 Markdown 后按短前缀猜页码。空白延续块通过原文的唯一首尾匹配，恢复跨页、跨栏的段落边界。无法确定的位置不会强行排序。
4. 算法区域默认展示 PDF 原文截图，包含相邻算法标题，可点击放大。组合识别的文本折叠在“识别文本（待核对）”中，保留代码块供辅助检索；加入对话时同时附上原图和带版本、页码的候选文本，以截图为准。当前自动算法区域识别主要支持带连续行号及 `end procedure` 的算法，其余保留结构化引擎结果。
5. 检查页码、坐标、跨页顺序、整页缺失、公式语法、数学字形冲突、表格网格和部分数值遗漏。宽阅读区展示双栏和图文环绕，窄区按阅读顺序单栏显示。
6. 识别有冲突的公式/表格显示 PDF 原文裁剪。Pi 上下文保留来源、页码、块 ID、版本号和待核对说明，不能把质量检查等同于数学语义正确。

## 数据与恢复

- `data/parsed/<内容哈希>/versions/<版本>/raw/`：原始引擎输出、PDF 文字层、算法证据。
- 同版本的 `blocks.json`、`full.md`、`quality.json`、`run.json`、`assets/`：规范结构、文本导出、质量报告、运行信息、图片。
- `current.json`：当前采用的版本指针。原始输出和旧版本不覆盖。
- 首次解析通过结构检查后可采用；已有结果时，新解析/本地重建仅保存候选，必须点击`采用版本`才切换。结构错误或内容指纹不一致的版本不能采用。
- `预览`不会改变 Pi 使用的版本；`对比当前`按页比较；`本地重建`重用保存的引擎输出，不重新调用远端引擎。升级前缓存保存为旧版快照。
- 读取接口、Pi `read_paper` 和附件读取均为只读，不再读取时迁移或重排数据。
- 本次升级前备份位于 `data/backups/parse-before-v4-1788490975811/`，包含原缓存和相关旧代码。


最后一条要求本地服务运行，默认核对库中的 RRNCO、POMO、DynamoLLM；可在命令后指定其他论文 ID。截图保存在 `data/qa/parser-20260904/`。

## 明确边界

这不是对任意 PDF 的无损重建保证。文字层错误、扫描件、复杂合并表格、旋转文本和数学 OCR 仍可能需要原图核对。没有质量告警也不表示所有符号或数值已获语义验证；有告警的内容会显式带入 Pi 上下文。当前 unstructured 二次补充主要覆盖整页缺失，不是对所有低置信度区域进行全引擎投票。
