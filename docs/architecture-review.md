# PiPaper 架构审查与分阶段重构建议

本文件记录重构前的审查；当前实现及验收见 [architecture.md](architecture.md)。

审查日期：2026-10-05。代码基线：`40e2ede`，分支 `codex/unified-storage-rag`。

本次审查读取应用代码、依赖关系、构建脚本与测试结构，没有更改业务代码或执行模型调用。测试基线沿用上一轮记录：169 项，168 通过、1 跳过；构建通过。本报告中的使用频率判断是产品建议，没有用户行为统计支持。

## 结论

项目已值得进行架构重构。当前应用 JavaScript 共 132 个文件、约 25,417 行，已经形成文献、阅读、研读、选题、知识检索、写作和视频等独立业务。统一存储、解析版本、Pi 会话控制与检索流水线已有可保留的基础。

建议采用模块化单体：继续使用现有 Express、SQLite、文件系统、Milvus、Pi SDK 和前端构建工具，建立清楚的业务边界、平台服务和数据契约，分批替换现有实现。前端按业务组织组件与状态，后端按用例组织服务、仓储与适配器。需要隔离耗时任务时，再将运行器放到独立 worker 进程。

首要收益应当是：新增业务时少改其他模块；模型、网络和任务错误有一致处理；同一份原文和引用在阅读、检索、研读、选题中保持一致；不同页面的状态与样式可独立验证。

## 已核对的结构问题

| 问题 | 代码证据 | 实际影响 |
| --- | --- | --- |
| 启动入口成为前端公共库 | `src/app.js` 同时导出 state、HTTP、DOM、对话附件与弹窗并负责启动；29 个模块导入它。静态导入图有一个涉及 30 个前端模块的强连通分量。 | 修改一个公共能力容易牵动启动顺序；组件难以单独挂载和测试。 |
| 大模块混合不同职责 | `src/chat.js` 1243 行；`src/storagePanel.js` 1205 行，同时包含资料管理和知识检索；`src/reader.js` 773 行。 | 会话连接、消息渲染、编辑、检索与任务控制不易各自演进。文件长度只是定位线索，拆分依据应是职责。 |
| 服务启动、HTTP 与业务混在一起 | `server/index.js` 692 行，直接定义 38 个 API 路由，并在顶层执行迁移、恢复、维护与 listen。 | 隔离测试需要启动整个服务；新增视频或检索逻辑仍修改总入口。 |
| 通用会话反向依赖研读 | `server/native-harness.js:72`、`:165` 动态导入 `studies.js`；后者通过 study-model 等再次依赖 native-harness。 | 会话内核难以独立复用；新增业务容易继续增加条件分支。 |
| 三套模型封装 | `study-model.js`、`topics/model.js`、`rag/providers.js` 分别处理运行时、上下文预算、流事件、结构化输出与错误。选题和 RAG 又借用研读模块的通用函数。 | 同类模型故障可能显示不同错误，修复不会自动覆盖其他场景。各业务的内容校验仍应分别保留。 |
| 学术来源适配重复 | `search/engines.js` 与 `topics/sources.js` 分别处理 OpenAlex、arXiv 和结果规范化，网络实现也不同。 | 选题的代理、退避和下载修复不会自动作用于找论文；字段与出处容易分歧。搜索排序与选题证据规则应继续分开。 |
| 统一清单之上仍有分散运行器 | parser、studies、topics、RAG 各有自己的运行中 Map、取消与恢复代码；parser 在 done/error 与统一 succeeded/failed 之间映射。 | 状态已纳管，但任务执行规则仍重复。每种业务的检查点不能靠统一名称代替。 |
| 状态投影规则散落 | `store.js` 同步内存集合、SQLite legacy states、JSON 镜像及资源 metadata；解析还有 current.json 指针。`readJsonState` 已优先读取 SQLite。 | 应明确每类业务的权威仓储和投影更新边界，避免继续增添同步路径；无需把现有 JSON 镜像全部删除。 |
| 页面共用能力归属不清 | 选题导入 `src/study/ui.js` 的通用 UI；主阅读器直接导入 `server/parser/mdblocks.js` 的纯函数。 | 公共基础能力应提升到前端平台／shared，业务模块之间不应借用启动或后端目录。 |
| 视频页面依赖完整主界面启动 | `/videos` 复用 index.html 和 app.js；会话范围由 app.js 根据 pathname 判断，启动仍初始化阅读、搜索并读取论文与项目。 | 独立业务页应声明自己的上下文和依赖，按需启动模块，避免用 URL 推断全部运行状态。 |
| 页面主题接入遗漏 | `public/study.html` 加载 style.css 和 study.css，没有 theme.css；颜色变量目前只由 theme.css 定义。研读 app 也没有使用共用主题初始化。 | 独立研读页缺少颜色变量来源与跨页同步，属于优先修复项。此次未做浏览器视觉复测。 |
| 工程检查缺口 | package.json 只有 test/build/start/dev；仓库没有 `.github/workflows`。 | 已有测试可以保留，但缺少提交后自动验证、依赖边界检查和核心契约的静态检查。 |

依赖统计包含静态 import/export 与直接字符串动态 import；不覆盖运行时拼接路径、插件或第三方代码。这里只用于定位耦合，不将循环依赖数量当作业务正确性的证明。

## 目标边界

采用现有仓库逐步演进，模块同时拥有自己的路由、用例、状态与测试。目录名称可以调整，以下职责应当稳定：

| 业务模块 | 前端职责 | 后端职责 |
| --- | --- | --- |
| 文献与项目 | 文献列表、导入、项目归属、来源信息 | 文献身份、Zotero 适配、受管快照、项目关系 |
| 文档与阅读 | 原文、结构化正文、批注、版本、选区 | 解析版本、结构化文档、定位证据、阅读译文 |
| 研读 | 独立三栏、学习检查点、引导／自由提问 | 研读流程、评估规则、固定版本、成果快照 |
| 选题 | 独立报告、调查卡、来源检索与对话 | 选题阶段、证据核验、期刊／政策规则、报告 |
| 知识检索 | 查询、筛选、时间策略、证据与引用 | 入库用例、召回、重排、反思、时间判断、发布 |
| 写作与成果 | Markdown、LaTeX、图解与成果查看 | 生成成果、编辑修订、编译／渲染适配器 |
| 视频 | 独立播放器、截图、时间轴、后续资料库 | 视频来源、受管媒体、分析任务与产物 |

跨模块能力放到平台层：存储与资源目录、任务执行、Pi 会话与模型调用、学术来源传输、事件、配置与诊断。平台通过接口提供能力，具体业务在启动装配处注册工具、上下文与事件处理。

示意结构：

```text
server/
  bootstrap/               创建应用、装配模块、启动与退出
  platform/
    storage/               保留并演进现有清单与文件机制
    jobs/                  任务登记、执行权、检查点与取消
    ai/                    Pi 会话适配、模型调用与用量事件
    academic/              来源适配、网络与元数据规范化
  modules/
    library/ documents/ study/ topics/ retrieval/ writing/ media/
src/
  shell/                   导航、布局、模块加载、页面启动
  platform/                HTTP、事件、持久化、主题、公共 UI
  features/
    library/ reader/ study/ topics/ retrieval/ writing/ media/
shared/
  contracts/               DTO、状态、引用与事件协议
  document/                纯文档处理与展示约定
```

每个业务模块内部保留自己的用例和内容规则；公共平台负责重复的基础机制。路由调用用例，用例调用仓储与服务，启动入口负责组装。禁止平台反向导入具体研读、选题或视频业务，禁止前端模块反向导入启动入口。

## 前端应如何对应重构

1. 将 app.js 的公共导出移到明确的 HTTP、DOM、附件、状态模块；app.js 只负责启动和装配。组件通过上下文接收依赖。
2. 主界面、研读、选题、视频使用共同应用壳与设计变量，保留各自的页面布局。公共主题、字号、弹窗、证据卡、消息、译文、任务状态与空态统一实现。
3. 状态按功能归属：文献选中状态、会话连接状态、检索结果、编辑草稿分别由对应 store 管理。统一 persistence 继续负责偏好、草稿与布局持久化，不承担所有业务逻辑。
4. 显式传入 WorkspaceContext：项目、资源、来源版本、会话范围与权限。不要从全局 currentPaper 或 pathname 推断视频、研读和选题的全部上下文。
5. 将 chat.js 拆为会话控制、消息／执行记录、输入附件和高级操作；将 storagePanel.js 拆为资源、任务、核对、回收站与检索功能。检索应有自己的功能入口代码，资料只通过业务动作触发重建与查看证据。
6. 逐步用可挂载组件替换固定 DOM ID 搬迁。提供 mount、activate、deactivate、dispose 生命周期，保持切换视图时的草稿与结果；为销毁清理请求、事件和对象 URL。
7. 按功能加载播放器、PDF、LaTeX、图解和编辑器。选择当前模块时才加载其代码与数据；页面不必先初始化全部隐藏工具。

类型化从共享契约和服务边界开始，再逐步迁移高变动模块。优先契约：

- ResourceRef：稳定资源 ID、来源版本、发布代次。
- Document / Block / Element：标题树、页码、坐标、原文证据、元素引用。
- Citation：资源／版本、块或元素、页码、来源日期及日期精度。
- Job：执行状态、阶段、进度、能力、检查点、配置指纹与发布权限。
- Artifact：笔记、报告、图解、译文、视频产物的归属、来源和快照关系。
- ConversationScope / StreamEvent：会话归属、内容／思考／工具／用量事件。

例如选区翻译可共用选择菜单、公式保护、译文组件、取消与缓存机制；阅读翻译与检索翻译继续分别提供来源校验和模型选择策略。

## 实施顺序与交付边界

### 第一批：修复明确遗漏并建立边界

- 修复研读页面的主题接入与资源版本戳。
- 核对并撤掉 LibreTranslate 遗留与旧 merge 文件，保存旧数据兼容路径。
- 提取前端 HTTP、DOM、状态与附件基础能力，解除 app.js 反向依赖。
- 建立 createApplication 与显式启动／退出，将入口路由按业务移出。
- 增加核心契约检查、依赖边界检查、CI 的测试与构建。

验收：启动入口只装配；上述前端循环依赖解除；所有现有入口、数据与 API 兼容；四类页面主题与核心交互回归通过。

### 第二批：合并模型、网络和任务机制

- 建立 ModelGateway 与学术来源适配，保留各业务提示词和校验器。
- Pi 会话通过注册上下文、工具及会话更换处理接入业务，解除 native-harness 对研读的反向导入。
- 将解析、入库、研读、选题和生成成果接入一致的任务执行接口。
- 明确任务能力：可取消、可重试、可暂停、可恢复并不相同；在检查点暂停，外部引擎不支持暂停时显示实际能力。
- 引入执行权／心跳与发布代次检查，为后续独立 worker 留出接口，继续使用已有 SQLite 持久化机制。

验收：一个模型或来源问题只需修复公共适配；取消、删除、重启与迟到结果保持现有保护；研读和选题业务状态不被任务状态替代。

### 第三批：领域仓储与页面组件

- 为文献、文档、成果、研读、选题提供明确仓储，统一投影提交与资源注册。
- 收敛 generic legacy states、资源 metadata 和 JSON 镜像的更新责任；大正文、解析输出和原始证据继续保存为文件。
- 拆分大前端模块，共用渲染、选择、译文和证据组件，按功能加载。
- 视频页面独立启动并显式声明会话范围，保留 `/study/:id`、`/topics/:id` 与已有文档链接。

验收：当前版本、历史引用、标题路径与附件不变；多页面与多个会话不串状态；查询、编辑和学习草稿恢复通过。

### 后续：独立业务扩展

在稳定契约上增加视频资料库、图谱、研究资料关系与更丰富的人工标注检索评测。按实际资源消耗决定是否独立运行解析／入库 worker。

## 验收原则

保留现有测试中对删除、共享资源、版本、迟到响应、引用与会话隔离的验证，逐步改为通过模块接口构建测试依赖。新增有实际意义的页面流程验收：独立页面主题、检索到证据到选区翻译／引用、研读任务恢复、选题历史报告、视频会话隔离，以及编辑草稿恢复。

每批可独立审查、提交与回退。目录移动与行为修改分别提交；先保证契约与兼容适配，再删除旧入口。维护已有文献 ID、固定解析版本、已保存成果、会话 JSONL 和旧附件链接，避免架构重构触发全库模型调用或自动入库。
