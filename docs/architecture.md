# PiPaper 当前架构与开发约定

本轮从 `40e2ede` 创建 `codex/modular-architecture`，将现有应用演进为模块化单体。继续使用原来的 Express、原生 DOM、esbuild、SQLite、文件系统、Milvus 和 Pi SDK。

## 已落地的边界

| 范围 | 当前实现 | 开发约定 |
| --- | --- | --- |
| HTTP 装配 | `server/application.js` 创建应用，`server/index.js` 调用 bootstrap 启动 | 新路由进入所属模块；入口不定义业务 API |
| 启动与退出 | `server/bootstrap/` 管理文献迁移、清单恢复、入库续跑和维护；退出时取消运行器、关闭 Pi 会话、刷新索引镜像 | 创建 HTTP 应用不会 listen，也不会启动入库续跑与维护定时器；旧配置／仓储导入和选题路由仍有初始化与恢复行为 |
| 业务路由 | `server/modules/` 按文献、学术检索、写作文件、媒体、摘录、设置划分 | 现有研读、选题、解析和存储入口兼容保留，逐步迁移，不为搬目录改 URL |
| 模型调用 | `server/platform/ai/gateway.js` 处理流、输入预算、图片能力、取消、用量和结构化载荷 | 业务保留模型选择、提示、验证与重试；provider 支持条件集中处理 |
| 会话上下文 | `session-scopes.js` 接受匹配会话归属的业务适配器 | Pi 会话不动态导入研读；研读注册上下文注入与会话更换回调 |
| 学术来源 | `server/platform/academic/` 共用网络、代理、压缩解码、公开地址校验、元数据和 arXiv 节流 | 找论文保留排序与返回形状；选题保留滚动时间窗口、证据门槛及配额处理 |
| 后台执行 | `ExecutionRegistry` 管理进程内执行权、并发排除、取消与释放 | SQLite 仍持久化任务状态；领域检查点和发布代次校验仍由业务负责 |
| 任务仓储 | 研读、选题共用 `createTaskRepository` 写任务、修订号、时间戳及资源元数据 | 业务负责合法状态与输入规则；SQLite 为内容权威，JSON 仍是兼容镜像，任务发现仍使用原目录 |
| 前端公共能力 | `src/platform/` 提供 HTTP、DOM、Markdown、UI、存储客户端 | 功能不导入 app.js，也不导入 server 目录；通用 UI 不借用研读入口 |
| 前端状态 | `features/library/store.js` 与 `features/chat/store.js` 分别拥有文献与会话状态 | `shell/state.js` 是旧面板兼容投影；新增功能直接使用对应 store |
| 前端协作 | 启动层给 sidebar、reader、chat、settings 传回调 | 功能不通过互相动态导入形成环；跨功能动作在装配处连接 |
| 知识检索 | `features/retrieval/panel.js` 独立挂载检索与证据视图 | 存储管理负责资源、任务、核对与回收站；检索负责查询与证据 |
| 文档处理 | `shared/document/markdown.js` 保存无运行时依赖的转换函数 | 解析与前端共用纯函数；旧 parser/mdblocks.js 只做兼容导出 |

主入口原有 38 个直接 API 已移至业务路由文件。前端原来的 30 模块循环，以及剩下的阅读／对话、设置／资源循环均已解除，当前导入图循环数为 0。

## 模型调用和任务安全

研读、选题、RAG 通过同一个模型网关调用 Pi。公共层不判定论文讲解是否完整、选题证据是否充分或扩写是否被原文支持，这些校验仍在相应业务内。模型服务错误、空输出、截断和取消保持可区分；无图片能力时，研读可明确降级到图注讨论，RAG 视觉补全必须换可用视觉模型。

任务取消后执行权保留到任务退出，阻止重复启动。释放必须携带当前运行器对象，因此旧运行器迟到的 finally 不能清掉后继任务。RAG 的 epoch、资源 revision 与发布检查继续保留。解析仍依赖外部引擎完成后核对发布权限，取消信号不会假装能强制终止不支持取消的引擎。

执行登记目前只覆盖单进程。多 worker 的持久化租约、心跳、争抢与跨进程取消还未实现，不能据此启动多个应用进程同时写同一数据目录。

## 保留与清理

- 文献 ID、解析版本、固定研读版本、会话 JSONL、成果目录和附件 URL 保持兼容。此重构不自动调用模型、不触发全库入库。
- 阅读、粗读、独立研读、独立选题和视频功能保留。没有按未知使用频率删除已有成果。
- 删除未使用的 LibreTranslate Compose 服务和默认 translate.url；模型翻译配置与 API 保留。旧本地配置若含 translate.url，不再消费该字段。
- 删除无消费者的旧 parser/merge.js；当前 pipeline、document、版本回放与遗留解析转换保留。
- 粗读生成改用已有临时 Pi 会话执行器，与图表生成、编辑器共用控制权隔离、事件与清理逻辑；失败会话仍保留供回查。
- 独立研读页面补齐 theme.css 和共用主题初始化；构建为主界面、研读、选题分别计算所有相关样式和脚本的版本戳。

## 工程检查与验证

```bash
npm run check
npm test
npm run build
```

check 对应用、脚本与测试做 JavaScript 语法检查，对 src/server/shared 的字面量 import 做边界分析，并拒绝前端循环依赖。它不解析插件计算出的导入路径，也不替代运行时测试。共享契约目录提供状态常量和 DTO 类型声明，目前尚未启用全仓 TypeScript 检查。

GitHub CI 配置 Windows 和 Linux 的 Node 24 检查、测试与构建；本轮仅在本机实际运行，远端执行结果需 push 后查看。

本机验收：175 项测试，174 通过、1 项可选真实 Milvus 测试跳过；构建与边界检查通过。新增覆盖模型最终消息和用量、结构化开关、取消迟到响应、截断／错误、执行权、会话适配器、学术元数据和拆分后的 HTTP 入口。现有存储、版本、删除、重启、研读、选题、翻译和会话测试继续通过。

浏览器验证了现有文献列表、论文切换、会话恢复、知识检索面板和历史研读页面。本轮未重新进行真实百炼、视觉模型和 Milvus 入库评测；模型自动测试使用隔离夹具。

## 后续迁移边界

已有兼容入口允许逐模块继续迁移：

1. 将大型 chat 消息视图、reader 控制器继续拆为具有 mount/dispose 生命周期的组件，完善页面级状态隔离。
2. 视频改为独立启动入口并按需加载 PDF、写作和图解；目前仍复用主界面壳，只通过显式 workspaceContext 供 API 与欢迎页识别会话范围。
3. 将文献／项目仓储的内存集合、SQLite 与延迟 JSON 镜像统一到明确的投影提交机制；当前只收敛了研读与选题任务写入。
4. 逐步收敛 Pi 业务工具和权限策略到注册接口。当前移除了研读上下文反向导入，既有业务工具与研读会话限制仍由兼容内核保留。
5. 逐步接入 TypeScript 契约检查，按实际负载引入 worker、租约和心跳。图谱继续作为独立业务规划，不引入 GraphRAG。
