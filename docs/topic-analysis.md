# 一次选题分析

入口 `/topics`，沿用页面内三栏导航。任务、画像快照、模型记录、检索记录、全文、统计、报告和独立对话保存在 `data/topic-analysis/`。

## 检索与 Baseline

1. Pi 模型先抽取中英文关键词，区分任务、方法、工具和应用背景，将大方向拆成 6–12 个独立问题。
2. 每条英文检索式最多组合两个核心术语，每词组至多5词。少结果时尝试同义词、单个具体任务词；skill acquisition 等歧义词不独立扩大检索。OpenAlex 兼顾相关度、最新与近年高被引，Crossref 补充发表元数据，arXiv 仅补充发现与开放全文。
3. 来源异常与零命中分开保存。中栏展示关键词、分支、检索式和每个问题的核验覆盖。
4. 主 Baseline、对照和衍生 Baseline 都必须在滚动近三年内，且满足中科院**大类 1 区**或 **CCF A 类正式长文**。未核实来源不进入 Baseline；CCF 期刊、SJR Q1、JCR Q1 不代替中科院 1 区。
5. CCF 核验使用第七版正式目录（2026 年），逐篇核对 ACL long、CVF 主会、ICML 论文集、ICLR 正式录用、NeurIPS 论文集及数据库会议研究长文。未适配会议保留待核验。目录来源与页码保存在 `server/topics/ccf-2026.json`，不能把所有 OpenReview/MLR 条目都算顶会。
6. 中科院官方证据必须定位到期刊，含 ISSN、年份和大类分区。可用中栏「来源」补充官方分区页面并指定 OpenAlex 来源 ID。没有官方证据时保持未知。
7. 正式发表身份与开放全文分别核验。读取全文时再次核对标题，防止 OpenAlex 的错误 OA 链接被关联到别的论文。GitHub README/许可通过官方公开 API 读取。

OpenAlex 可使用环境变量 `OPENALEX_API_KEY` 或 `data/config.json` 的 `topicAnalysis.openalexApiKey`。密钥不进入检索 URL、日志或前端明文。

日配额耗尽时遵守服务端重试时间，在当前分析内暂停 OpenAlex，继续其他来源，不重复请求耗尽的配额。期刊统计可降级到 Crossref：按核验过的 ISSN 逐页读取近三年及当年全部已注册期刊论文，在题名和已提供摘要中匹配最终问题的具体英文短语。统计口径及短语在每张期刊卡片内明确显示；未遍历完整的数据保持未知，不生成零值或增长率。该统计衡量明确短语的可观测发文量，不等于整个主题的总文献量。

## 证据与统计边界

- 公开论文不等于公开数据；数据要求公开声明或许可证、可读取入口和与主 Baseline 的关联。
- GPU 卡数/显存只按原文证据匹配。调查卡未填数字时不擅自猜测。已有 API/CPU 原文证据的路线不因缺少 GPU 数字被误排除，但接口成本和实验时长仍需试跑。
- 审稿时间缺失时保持未知，区分首次决定、外审与录用周期。
- 近三年趋势使用三个完整自然年，当年单列。期刊统计围绕最终 Baseline 支撑的问题检索式，避免宽泛业务词污染投稿报告。
- 当日真实检索快照允许续跑；范围、日期或目录版本改变必须重新检索。删除任何依赖证据会清理依赖报告和对话记忆。

## 验证

`npm test` 覆盖持久化/删除/取消、查询放宽、来源失败、重复文献、正式发表身份、日期、分区和证据约束；`npm run build` 构建前端。

真实回归可运行 `node scripts/topic-live-retrieval.mjs <已保存任务ID>`。该命令使用当前 Pi 模型与真实来源，输出到 `data/topic-live-validation/`，不调用测试 fixture。`scripts/topic-run-saved.mjs` 用于在现有服务不运行该任务时续跑并保存报告，不重启服务。
